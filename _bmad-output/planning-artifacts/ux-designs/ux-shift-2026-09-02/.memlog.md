- (event) Rendered .working/color-themes-1.html: 4 palettes (Vatrogasna / Operativna / Papir / Nocna smjena) each shown light+dark with the pilot's real content, plus 3 modifier-encoding strategies (glyph+fill / typographic+rule / corner marker) on a neutral base, plus the typeface constraint table. 49 diacritic-bearing strings included so a font gap shows immediately.
- (note) FINDING surfaced to user: PRD allows the pilot a fire-department red accent while the spec requires unresolved conflicts to be visible at a glance. Brand red and conflict red being the same red makes the alarm colour read as furniture. Resolution must be one of: brand accent avoids red, or conflict is not carried primarily by hue. Not decided by me.
- (decision) STRUCTURAL PROPOSAL put to the user: the seven states are not peers. Three are BASE states (the shift type - Organization data, arbitrary count) and four are MODIFIERS (leave, conflict, uncovered, overridden - system-defined, fixed forever). Therefore colour carries the base state and a non-colour signal carries every modifier. This is what makes DI-8 ('must work for shift types the design never anticipated') satisfiable rather than a fight.
- (note) Typeface constraint stated as fact, not preference: Croatian needs Latin Extended-A (c-caron, c-acute, z-caron, s-caron, d-stroke) or the UI falls back mid-word in shift names, month names and member names. Tabular numerals also required for the hours table and time ranges. Candidates named; pick left to the user.
- (decision) PALETTE: variation 2 'Operativna'. Steel neutrals, single blue accent #1F6FB2, danger #D93A46 RESERVED exclusively for conflict. Chosen over the fire-service red option, which resolves the brand-red/conflict-red collision structurally: the brand accent can never be the alarm colour. Also the honest fit for a platform where accent is meant to be Organization data.
- (decision) DARK MODE: ship both themes driven by prefers-color-scheme, with NO in-app toggle and no settings surface. Consequence: every meaning-bearing state (base shift types + 4 modifiers) must be verified for contrast in both themes; there is no light-only escape hatch.
- (decision) MODIFIER ENCODING: strategy A, glyph + fill weight. A small mark precedes the label and fill density changes: hatching for leave and uncovered, inset ring for overridden, glyph for conflict. Chosen for information density and because it scales to any shift-type count. Accepted cost: four glyphs is a legend the user must learn, so a persistent legend is now a required calendar affordance.
- (decision) TYPEFACE: Geist, shadcn's default, inherited wholesale. Covers Latin Extended-A and offers tabular figures. Consequence: DESIGN.md carries ZERO typography delta -- typography section documents the inheritance and the tabular-numeral requirement only.
- (note) Combined consequence of the palette + encoding picks: colour now carries ONLY the base shift type (org data, arbitrary count) and the single reserved danger hue; all four modifiers are carried by glyph and fill treatment. This satisfies both DI-8 and the no-colour-alone accessibility floor by construction rather than by review.

Satisfies the spec's small-viewport priority order for members AND 'every admin task completable on mobile' for admins, without a separate admin calendar.
- (decision) 24-HOUR DUTY: merged presentation ('Duty block'). Consecutive working shifts with no non-working interval between them present as ONE duty with an end time and progress. The data model is untouched - still two Scheduled Shifts on two dates per DI-5; only the presentation merges.
- (decision) DERIVED from the duty-block pick, flagged for confirmation: the calendar's organising axis is dates, so it still renders two cells for a 24h duty. Merged presentation there means the two cells are visually LINKED with a continuation marker rather than collapsed into one cell. Collapsing would break the date grid and contradict DI-5's start-date attribution.
- (decision) MOTION: minimal. Inherit shadcn component transitions (dialog, sheet, popover) and add nothing. DESIGN.md carries no motion tokens and no motion section. Rationale accepted: a member checking a rota in ten seconds is never helped by animation, and low-end phones pay for it.

- (decision) CONFLICT RESOLUTION: per-conflict only. No bulk-resolve affordance anywhere. Each conflict is decided on its own screen with its own consequences displayed. Accepted cost: a two-week absence means four separate decisions.
- (decision) CLARIFICATION on the no-bulk rule: 'Amend Leave' still clears every conflict its record caused. That is cause-removal (one edit to one leave record), not batch resolution of conflicts, so it does not violate the stance. Accept-as-Uncovered and Replace-Member remain strictly per-shift because each is a distinct coverage decision.
- (decision) CONFLICT SCREEN DISCIPLINE: no option is primary-styled and none is labelled recommended, because a visual default is a decision made for the admin. Every option states its outcome in the same three terms so outcomes are compared, not guessed.
