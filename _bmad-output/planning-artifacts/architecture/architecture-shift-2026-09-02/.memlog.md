- (decision) PARADIGM. The database stores only what a human asserted; everything else is a pure function of it. Persisted: rules (org settings, hour bands, shift types, rotation patterns and assignments, teams, members, allowances), exceptions (shift-type overrides, roster overrides, leave records) and decisions (conflict resolutions, with their attribution). Derived, never stored: projected schedule, shift rosters, band hours, total hours, leave-day counts, leave balances, leave/schedule collisions, coverage and rest-gap warnings. Binds every unit that touches schedule data. Prevents the drift where one unit reads a materialized row and another recomputes, and makes DI-1 and DI-2 properties of the store rather than disciplines the code must maintain.
- (decision) Q1 RESOLVED - compute on read, chosen by user over materialize-with-horizon and cache-on-demand. Decisive argument was quality-requirements Q18 ('navigating to any month, past or future, performs comparably whether or not that range has been visited before'), which a horizon makes false by construction and compute-on-read makes true by construction. Q17's 2s all-teams-month budget is not threatened: a 30-day 4-team projection is ~120 modulo operations and the cost centre is the round trip, not the arithmetic. The month query reduces to the exception layer, whose size tracks how much actually happened rather than how large the calendar is.
- (decision) Q4 RESOLVED - a Conflict is DERIVED, never stored; what is stored is its resolution, keyed by (organization, member, date). An unresolved conflict is a derived collision with no matching resolution row. Chosen by user over stored-rows-written-in-transaction and derive-then-snapshot. The winning property: 'a conflict exists iff there is a real collision with no resolution' becomes true by construction, so none of the six recomputation events can ever be missed - the failure the product exists to prevent becomes structurally impossible rather than a discipline. Attribution (Q11) is unaffected because resolutions are rows. A Postgres trigger doing detection was ruled out earlier as a second implementation of conflict detection in PL/pgSQL, which quality-requirements Q8 forbids explicitly 'even when both copies agree today'.
- (decision) R2.10 / addendum Q2 RESOLVED by consequence, not by preference: Rotation Assignments are VERSIONED with validity ranges, and projection selects the version covering the date being asked about. Compute-on-read forces it - with no stored shifts, the rule's own version history is the only thing making history stable, so an in-place mutation silently re-projects every past date through the new pattern and breaks CAP-9's 'shifts before the effective date are unchanged'. In-place mutation is not a lighter option here, it is incorrect. Stated to the user as forced rather than offered as a choice.
- (decision) Illegal states are made UNREPRESENTABLE rather than validated - the Hour Band editor principle from EXPERIENCE.md generalized to the schema. Hour bands stored as name + start time only (gap/overlap unrepresentable); a Rotation Offset stored as an FK to a step OF THAT PATTERN rather than an integer (R1.6 outside-cycle unrepresentable, and R1.5's empty pattern falls out free since it has no step to reference); no overlapping leave per member enforced by EXCLUDE USING gist on the member and the date range (R4.4). Enabling distinction, and the reason quality-requirements Q8 is not violated: a CONSTRAINT is a declarative guard, not a CALCULATION - EXCLUDE USING gist reimplements no leave logic, whereas a trigger computing conflicts would be a second implementation. The zero-admins rule (Q6) is the one refusal that cannot be designed away and needs a real guard.
- (decision) Vanish problem RESOLVED - diff and surface for review. A configuration change computes the derived collision set before and after and diffs it; any UNRESOLVED collision the change would erase is surfaced for explicit confirm/amend/discard, the same treatment CAP-9 already mandates for overrides on a rotation change. Chosen over letting cause-removal clear silently and over refusing the config change outright (which would have contradicted CAP-10's warn-never-block stance). Only possible because collisions are derived - a before/after diff of stored rows would be reconciliation, not a diff. Cost accepted: a config save now runs a before/after projection.
- (decision) Write path RESOLVED - NO server tier. Clients write directly via PostgREST; RLS enforces tenant and role, schema shape makes illegal states unrepresentable, and attribution comes from column defaults the client cannot forge (auth.uid(), now()). The Edge Function write tier was bought largely to guarantee conflict recomputation could not be bypassed, and the derived-conflict decision removed that problem entirely. Chosen over an Edge Function tier and over defer-until-forced. Consequence to watch: any future integrity rule must be expressible declaratively or it has nowhere to live.
- (decision) Auth identity RESOLVED - admin-issued username mapped to a synthesized non-routable address in auth.users, verified necessary because Supabase Auth binds a password to an email or phone and has no native username identity (supabase.com/docs/guides/auth/passwords, checked 2026-09-02). Satisfies CAP-1's 'usable member account with no email address present' and quality-requirements Q5 data minimization. CONSEQUENCE, load-bearing for CAP-1's password reset: email-based self-service reset is impossible for these accounts, so reset is an admin-issued action. Chosen over optional-real-email-with-username-fallback (two identity paths and two reset flows) and over phone identity (pulls new personal data in against Q5, adds SMS cost and a provider dependency, still fails for a member with no number).
- (constraint) Addendum Q3 (history immutability / period locking) is NOT an open question - it is already settled by the SPEC non-goal 'Not payroll or time-and-attendance ... no rates, pay, overtime, premiums, breaks, period locking, or government reporting.' History stays mutable with attribution per DI-11. Inherited silently rather than re-asked.
- (decision) RLS shape RESOLVED - SPLIT. organization_id rides in a JWT custom claim via an access token hook; role and active status are read fresh on every policy evaluation through a SECURITY DEFINER STABLE helper against the members table. The split is safe ONLY because of the existing non-goal 'one user in exactly one organization', which makes organization_id immutable for a user's lifetime so a cached claim can never be wrong. Rejected all-claims, the common Supabase idiom, because claims are stale until token refresh and that contradicts CAP-4 ('deactivation blocks authentication') and quality-requirements Q2 ('refused identically whether through the UI or a direct API call') - it would have accepted a bounded window in which a demoted admin still writes. Rejected all-lookup because it pays a lookup for the org scoping that provably never changes. Cost accepted: one indexed lookup per statement plus an access token hook to maintain.
- (decision) Read shape RESOLVED - ONE SNAPSHOT PER SURFACE. Each surface fetches one composite payload (configuration plus the exception layer for its window) under a single TanStack Query key, and every figure rendered on that surface is derived from that one snapshot by the domain package. Makes quality-requirements Q19 ('no screen shows a stale total beside a fresh one') true by construction: two figures cannot disagree because they came from the same read. Rejected fine-grained keys with disciplined invalidation, which would have made Q19 a discipline every future mutation author must uphold - the exact class of invariant two independently-built units answer incompatibly. Rejected one org-wide snapshot because Q20's several-hundred-member case turns it into a scaling cliff. Cost accepted: coarser cache granularity and some over-fetch; a mutation refetches a surface rather than a field.

- (decision) TIME REPRESENTATION. All domain arithmetic is integer MINUTES SINCE MIDNIGHT over nominal wall-clock; no Date object, no timestamptz, and no instant ever enters a calculation. Shift Types store start_time and end_time as time-without-time-zone plus an is_working flag; nominal duration is DERIVED (end <= start implies it crosses midnight, so add 1440). Hour Bands store name + start time only, their windows derived from the next band's start. Instants are computed only for display in the organization timezone and never for accounting. Binds every unit computing hours, durations, projections or band intersections. Prevents the DST class of bug outright: DI-6 ('a 12-hour night shift reports 12 hours on daylight-saving transition dates') becomes unfalsifiable because elapsed real time is never consulted, rather than a rule someone must remember.
- (decision) DOMAIN PACKAGE. One workspace package (packages/domain) holding rotation projection, roster derivation, band intersection, hour totals, leave-day counting, balance, collision derivation and configuration warnings. Pure TypeScript, zero runtime dependencies, no React import, no Supabase import, no I/O. Signature shape is (configuration snapshot, exception layer, window) -> derived values over plain data. Binds every consumer: the app may not recompute anything the package computes, and the package may not reach for data. Prevents quality-requirements Q8's duplicate-implementation failure structurally - there is exactly one place the arithmetic can live, and it cannot accidentally acquire a data-access dependency because it has no client to import.
- (decision) DOMAIN OUTPUT IS DATA, NEVER PROSE. Warnings, refusals and states are returned as codes with numeric operands - for example {code:'REST_GAP', hours:24} and {code:'COVERAGE_GAP', dates:[...]} - and the UI resolves them through the i18n layer. Binds the domain package and every surface rendering a warning. Prevents localization L4's violation ('a function that returns 12 sati instead of 12 is a defect') and is what makes L7's Croatian three-form plural rule expressible at all, since the count must reach the formatter as a number.
- (decision) ATTRIBUTION BY COLUMN DEFAULT. Every override, leave record and conflict resolution carries created_by uuid default auth.uid() and created_at timestamptz default now(), with an RLS WITH CHECK asserting created_by = auth.uid(). Binds every write. Prevents a forged or absent author: the client cannot supply a different uuid and cannot omit one, so DI-11 and quality-requirements Q11/Q12 hold without an audit-log table and without trusting application code - which matters more than usual here because there is no server tier to enforce it.
- (decision) TESTING. Vitest in the node environment, no jsdom and no browser, per quality-requirements Q9. Binds where a rule may be verified: a rule asserted only through a rendered component does not count as covered.
- (decision) NO SERVER RUNTIME. The frontend is a static SPA build deployed to any static host; there is no application server, no SSR and no Edge Function in MVP. - (decision) ADVERSARIAL FINDING 1, the serious one - AD-2 generalized from 'rotation assignments are versioned' to 'every rule that feeds derivation declares whether it is versioned or current-state', with a classification table. Under AD-1 nothing is stored, so a rule edit re-derives every past date through the new value BY DEFAULT. AD-2 had covered rotation assignments and left team membership and member active status current-state - the identical bug with a wider blast radius, quietly violating CAP-4 ('deactivation alters no past shift', also engine-rules R7.4) and CAP-6 ('a team move changes the schedule forward only and rewrites no history'). Classified versioned: rotation assignment, team membership, member active status, rotation pattern and steps. Classified current-state: hour bands (CAP-3 explicitly WANTS retroactivity - moving a boundary recomputes reported band hours) and leave allowance (CAP-15 - allowance minus used equals balance at all times). A new rule kind is unclassified until it enters the table.
- (decision) ADVERSARIAL FINDING 2 - conflict_resolutions key corrected from (organization, member, date) to (organization, member, date, team). The three-part key was not unique: a Roster Override can place a member on ANOTHER team's shift on a date they already work, producing two distinct collisions the same day that the original key would have collapsed into one - silently discarding a decision.
- (decision) ADVERSARIAL FINDING 3 - AD-5's before/after diff was unbounded over all future dates. Bounded: a collision requires a leave record, so the window is the union of existing leave ranges intersected with the change's own validity range. Without this an epic could reasonably have implemented an unbounded projection on every rotation save.
- (decision) ADVERSARIAL FINDING 4 - added the canonical-snapshot convention. AD-13 fixed that each surface reads one snapshot but not what a snapshot IS, so two surfaces needing the same override/leave/resolution rows could each define their own payload type with different field names - two units obeying every AD and still diverging. One OrganizationSnapshot(window) type; surfaces narrow it by selection and never redefine it.
- (decision) RECONCILE FINDING - quality-requirements Q6 (an organization is never left with zero admins; the last admin's role cannot be downgraded) had been reasoned about during coaching as 'the one refusal that cannot be designed away' and was then dropped by the AD structure. Restored into AD-3 as a named exception: it is a cross-row cardinality rule, so it cannot be made unrepresentable by schema shape and is enforced by a constraint trigger. Declared THE ONLY permitted trigger - a second one is a signal that AD-9's no-server-tier decision needs revisiting rather than a licence to write more triggers. AD-3 also now names the btree_gist dependency explicitly. Reconcile otherwise clean: Q4, Q17 and Q20 all present via Deferred entries.
- (decision) TRIAGE BLOCKER RESOLVED - shift types classified in AD-2, splitting the entity: TIMES are versioned, NAME is current-state. Times versioned because an edit would otherwise change accepted totals for closed months with nothing recording it, and period locking is an explicit non-goal so nothing would catch it - which would undercut the success signal's 'two consecutive months of hour totals accepted without manual recomputation'. Materially worse than the hour-band case the user already sanctioned, since CAP-3's retroactivity explicitly 'changes no total' while a shift-type time edit changes the totals themselves. Name left current-state so a typo fix does not create a version on the engine's hottest path. Rejected pure current-state, and rejected immutable-times-with-forced-new-type (a hard refusal on what feels like a simple correction, cutting against CAP-10's warn-rather-than-block posture). - (decision) API KEYS, closing readiness Finding 3. Supabase's legacy anon/service_role keys are deprecated at the end of 2026 in favour of publishable (sb_publishable_*) and secret (sb_secret_*) keys. The SPA ships the PUBLISHABLE key only. The SECRET key exists in exactly one place - the privileged auth function's environment - and is never present in any client bundle, any committed file, or any migration. Binds every environment: local, staging and production each carry their own pair.
